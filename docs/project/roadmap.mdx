<Note>
  **Released** means the package is available on npm. EA can still change its
  upstream responses. The compatibility runner detects those changes; it does
  not guarantee upstream stability. The SDK does not use authentication: never
  send EA credentials, cookies, or session tokens. Keep live probes explicit,
  sequential, and low volume. See [Support and
  limitations](/docs/project/limitations) for the full operating guidance.

## Unreleased

- Added Nintendo player labels to `matches.list`: namespace `"4"` resolves to `nintendo` and, on `nx`, to `switch`. The raw namespace stays available. `switch` identifies the console family because EA does not distinguish Switch 2.

## 0.3.2

- Added runnable examples for a club dashboard and a Discord bot summary.
- Documented FC 27 platform changes, rejected requests, and known response limitations.
- Updated the README, documentation home page, and package metadata so developers can find the API reference and guides.
- Added documentation search metadata and social previews. The SDK runtime and its 11 typed methods are unchanged.

## What shipped in 0.3.1

- Checked the SDK against EA Sports FC 27 on 2026-09-30. `common-gen5` and `nx` pass the live compatibility probes on 10 of 11 endpoints. `clubs.playoffAchievements` stays unverified until clubs finish their first FC 27 playoffs.
- Deprecated `common-gen4`. EA rejects it with HTTP 400 since the FC 27 switchover. The value stays in `PLATFORMS`; a client emits one `DeprecationWarning` (`PROCLUBS_DEP001`) when a request uses it. Added `DEPRECATED_PLATFORMS`.
- Switched the documentation examples and the default compatibility probe to `HEMLE FC`, which exists on FC 27.
- Added a "Why this exists" section to the README. It states that the default transport sends a Chrome network profile and that a custom transport can replace it.

## What shipped in 0.3.0

- `matches.list` players keep the raw `namespace` and gain `derivedLabels.platformFamily` (`playstation`, `xbox`, or `pc`) and `derivedLabels.exactPlatform` (for example `ps5` or `xbox-series`), resolved from the requested platform.
- `friendlyMatch` rows have `namespace: "0"` and no derived platform.

## What shipped in 0.2.5

- Added standalone export subpaths (`proclubs-sdk/nationalities`, `proclubs-sdk/regions`, and `proclubs-sdk/metadata`) for importing pure label tables without loading `client.js` or native dependencies.

## What shipped in 0.2.4

- Added Belize, Nicaragua, Ethiopia, Swaziland, Bhutan, Brunei Darussalam, Guam, Malaysia, Mongolia, and Solomon Islands to `NATIONALITY_LABELS`.
- These ids are absent from the 2026-09-26 ratings filter and are used by live Pro Clubs members.

## What shipped in 0.2.3

- Added `NATIONALITY_LABELS` and `resolveNationality` for the EA nation ids captured on 2026-09-26.
- `members.stats` and `members.careerStats` keep raw `proNationality` and add `nationality` when the id is known.
- An unknown `proNationality` stays valid and is reported as drift. A null or non-object `derivedLabels` no longer drops the calculated nationality.

## What shipped in 0.2.2

- Added an opt-in strict mode that reports an immediate `403` instead of retrying.
- Released response resources before returning a strict-mode HTTP error.
- Updated Zod and development dependencies. The public endpoint surface stays at
  11 typed methods.

## What shipped in 0.2.1

- Added four ranking methods and `clubs.playoffAchievements`. The public client
  grew from 6 to 11 typed methods.
- Added exhaustive contracts for all 11 endpoints and sanitized drift reports.
- Kept unknown EA enum and region values visible without treating them as
  structural drift. Removed fields, changed types, rejected schemas, and empty
  responses still block a release gate.
- Added region, platform, match, division, reputation, playoff, and crest
  helpers.
- Added configurable live probes for `common-gen5`, `common-gen4`, and `nx`.

Read the [rankings reference](/docs/reference/rankings), [metadata
reference](/docs/reference/metadata), and [compatibility
reference](/docs/reference/types-and-schemas) for the full API details.

## Planned work

Planned items are approved for the roadmap, but have no delivery date. None is
currently in progress.

| Target | Scope | Boundary |
| --- | --- | --- |
| `0.4` | Optional relay CLI, healthcheck, route allowlist, shared-secret authentication, and Docker packaging. | The relay stays optional. The SDK continues to make direct server-side requests without it. |
| `0.5` | Circuit breaker, client-side rate limiting, stable-IP proxy support, and framework adapters. | Adds request handling and integration options around the SDK. |
| `1.0` | Stabilized public API, maintained EA compatibility matrix, and a single release and compatibility workflow. | The current on-demand probes become a maintained platform support policy. |
