---
title: "Nationalities"
description: "Resolve EA proNationality values to a nation label and ISO code."
---

EA Pro Clubs member responses identify a virtual pro's nation with a numeric
`proNationality`. The SDK keeps that raw identifier and, when the value is
known, adds a derived `nationality` on normalized members from `members.stats`
and `members.careerStats`.

<Warning>
  This mapping is reverse-engineered from the EA SPORTS FC website. It is not
  an official EA contract and can change without notice. Unknown IDs never fail
  a request: `proNationality` stays available and `nationality` is omitted.
</Warning>

## Where the table comes from

Captured on 2026-09-26 from
[the EA SPORTS FC ratings page](https://www.ea.com/games/ea-sports-fc/ratings).

The page embeds `props.pageProps.ratingsFilters.nationality` in its
`__NEXT_DATA__` JSON. Each item is `{ id, label, imageUrl, isPopular }`. The
flag asset is named `f_{id}.png` (`f_14.png` is England). The Pro Clubs
overview and member-list pages embed region translations only, so they do not
carry this table. Live `members/stats` payloads use the same numeric ids.

The ratings page listed Comoros (`214`) twice, with the same label and two
flag URLs. The SDK keeps one entry.

Labels are copied exactly from EA, including `Holland`, `Côte d'Ivoire`,
`Korea Republic`, `China PR`, `Cape Verde Islands`, and
`São Tomé e Príncipe`.

## Beginner example

```ts
import { ProClubsClient, resolveNationality } from 'proclubs-sdk'

const proclubs = new ProClubsClient()
const stats = await proclubs.members.stats({ clubId: '35303' })

for (const member of stats.members) {
  console.log(member.proNationality, member.nationality)
}

resolveNationality(14)
resolveNationality('14')
resolveNationality('  14  ')
// { id: '14', label: 'England', isoCode: 'GB-ENG' }

resolveNationality(999999)
resolveNationality(null)
resolveNationality('')
// undefined
```

`id` on the derived object is the canonical EA id as a string, the same key
used by `NATIONALITY_LABELS`. The raw `proNationality` is not rewritten, so a
numeric upstream value stays a number.

## ISO codes

`isoCode` is added by the SDK. EA does not send it.

- When the nation has an ISO 3166-1 alpha-2 code, `isoCode` is that code.
- England, Scotland, Wales, and Northern Ireland have no alpha-2 code of their
  own. `isoCode` is the ISO 3166-2 subdivision: `GB-ENG`, `GB-SCT`, `GB-WLS`,
  and `GB-NIR`.
- Chinese Taipei (`213`) and Kosovo (`219`) have no officially assigned ISO
  3166-1 alpha-2 code, so `isoCode` is omitted.
- EA's label for the Netherlands is `Holland`. `isoCode` is `NL`.

## Mapping and helper

```ts
import {
  NATIONALITY_LABELS,
  resolveNationality,
  type KnownNationalityId,
  type Nationality,
  type NationalityIsoCode,
  type NationalityLabel,
} from 'proclubs-sdk'

NATIONALITY_LABELS['14']
// { label: 'England', isoCode: 'GB-ENG' }

NATIONALITY_LABELS['213']
// { label: 'Chinese Taipei' }
```

- `NATIONALITY_LABELS` is a frozen object whose keys are the EA IDs as strings.
  Each value is frozen too.
- `KnownNationalityId`, `NationalityLabel`, and `NationalityIsoCode` are derived
  from that constant.
- `resolveNationality` accepts `string | number | null | undefined` and returns
  `{ id, label, isoCode? }` or `undefined`.
- Surrounding whitespace on string IDs is ignored. There is no partial match
  and no numeric coercion beyond the exact string or number EA sent.
- `null`, `undefined`, `''`, and a whitespace-only string resolve to
  `undefined` and do not throw.

If EA already supplies `nationality` on a member, that raw value is preserved
and the calculated value is exposed under `derivedLabels.nationality`.

## Drift detection

An unknown `proNationality` is valid at runtime so a new EA nation cannot break
`members.stats` or `members.careerStats`. The
[structural drift detector](/docs/reference/types-and-schemas) can report that
ID as `unknown_value` on a live compatibility check. `null` and an empty or
whitespace-only string are not reported: they mean the nation was not sent.
Maintainers then confirm the EA label and update `NATIONALITY_LABELS`
deliberately. The mapping does not depend on the full compatibility workflow.
