observed FC26 shapes described on the namespace reference pages.

## Runtime fidelity and normalizations

- **Runtime fidelity:** All object schemas use loose object validation, meaning any additional fields sent by EA are preserved and accessible on returned objects.
- **Envelope unwrapping:** `clubs.get` and `clubs.overallStats` unwrap the upstream envelope to return the requested resource directly (`ClubInfo | null` and `ClubOverallStats | null`), without modifying any nested fields.
- The other four endpoints (`clubs.search`, `members.stats`, `members.careerStats`, `matches.list`) return their full response data directly.

## Response schemas

The public Zod schemas let consumers validate stored or forwarded EA payloads
against the same envelopes as the SDK.

```ts
import {
  clubInfoResponseSchema,
  clubInfoSchema,
  clubMatchesResponseSchema,
  clubMatchSchema,
  clubMemberSchema,
  clubMemberStatsSchema,
  clubOverallStatsResponseSchema,
  clubOverallStatsSchema,
  clubSearchResponseSchema,
  clubSummaryInfoSchema,
  clubSummarySchema,

  listMatchesInputSchema,
  matchAggregateStatsSchema,
  matchClubDetailsSchema,
  matchPlayerStatsSchema,
  matchTimeAgoSchema,

```

```ts
const result = clubMemberStatsSchema.safeParse(untrustedPayload)

if (result.success) {
  console.log(result.data.members)
}
```

## Drift detection and compatibility

```ts
import {
  ENDPOINT_CONTRACTS,
  detectDrift,
  generateReport,
  runCompatibilityCheck,
  type CompatibilityReport,
  type DriftIssue,
  type EndpointDriftResult,
} from 'proclubs-sdk'
```

The SDK provides a deterministic structural drift detector that compares EA responses against the observed FC26 contract shape. It categorizes changes into `field_added`, `field_removed`, `type_changed`, and `envelope_changed`.

```ts
const drift = detectDrift('clubsSearch', searchPayload)
if (drift.status === 'drifted') {
  console.log(drift.issues)
}
```
